# Growth Map — Points Gamification + Full Reskin

Date: 2026-08-15

## Goal

Sarah and Mirayah earn points for correct worksheet answers: 1 correct answer = 1 point = ₹1 (real-money conversion is out of scope — parent handles payout physically or online, app just tracks points and lets parent zero the balance out). Kid completes a worksheet generated by the app, on paper. Parent photographs the completed sheet, AI estimates a correct-count against the sheet's saved answer key, parent reviews/corrects that count, then confirms — only then do points post. Whole site gets restyled to a calm-but-playful "Hybrid Zen-Play" look, not just the new screens.

**2026-08-15 revision (before plan-writing):** the original per-question ✓/✗ toggle grading design doesn't fit the real data model — read while starting the implementation plan. `ws.ans` is one free-text summary string *per block* (e.g. `"B: 14, 22, 9"`), not `{question, correctAnswer}` pairs per item, and the app already has a working manual mastery-check flow (`openMasteryCheck`/`confirmMastery` in growth-map.html) where the parent types a raw "X out of Y correct" count against the printed answer key to gate level-up at 80%. Rebuilding every `ws_*` generator (~12 functions, heavily fine-tuned across ~50 targeted-fix commits) to emit structured per-item answers was rejected as too large/risky for what this feature needs. **Revised approach:** AI returns one estimated correct-count (0–MTOTAL, the same MTOTAL the mastery modal already computes) + a short note, pre-filling the *existing* `mCorrect` input. Parent can still adjust the number before confirming. The existing "✓ Confirm & level up" button now also awards points equal to the confirmed count. One unified flow instead of a separate approval screen. All references below to "per-question toggle" are superseded by this.

## Scope

**In scope:** Maths, Science, English for both kids (the 3 subjects with real generated worksheets + answer keys). Points ledger + wallet UI per kid. AI-assisted grading via photo upload, with mandatory parent approval before any point posts. Cross-device sync (Supabase) so a kid's read-only balance view stays live regardless of which device the parent uploads/approves from. Full-site visual reskin to the Hybrid Zen-Play direction.

**Out of scope:** Swim/Music/Riding/Madhurim (practice-card subjects, no answer key — no points). Any real-money/payment logic, Amazon integration, or rupee conversion inside the app. Kid-initiated upload (parent uploads on the parent's device). Login/auth (stays a plain link, open RLS, matches the rest of the app's family-tool posture).

## Why cross-device sync is required now

The existing app is URL-hash-only for persistence today — a prior Supabase+localStorage sync layer was built 2026-07-22 and reverted the same day (reason not recorded in commit messages, and not recoverable from memory). This feature has a hard requirement that didn't exist before: a kid's balance must show correctly on their own device regardless of when/where the parent uploaded and approved a sheet. URL-hash can't do that. Supabase (same low-cost/no-login pattern as the original attempt) is being rebuilt specifically to carry `sheets` and `points_ledger`; nothing about the previous revert is known to block this, so it's being treated as safe to rebuild.

| column | type | notes |
|---|---|---|

Balance = `sum(delta) where kid = ?`. History view = ledger rows, newest first. Streak = count of consecutive calendar days (ending today or yesterday) with ≥1 `approved` sheet for that kid.

## Backend: `grade-sheet` Edge Function

Input: `sheet_id`, photo (uploaded to Storage first, function reads by path). Loads the sheet's `questions`/`answer_key`/`mtotal`, calls Claude with vision on the photo, asks it to estimate how many of the `mtotal` graded items are correct against the key, returns `{estimated_correct, note}`. Writes `ai_verdict`, flips `photo_url`/status to `pending_review`. Anthropic API key is a Supabase secret — never shipped to the client, matching the "no writes to booksgoat.com" style key-hygiene bar already enforced elsewhere in this environment.

**Failure mode:** if the call errors or times out, the sheet still moves to `pending_review` with `ai_verdict = null`. The mastery modal's `mCorrect` input simply opens at 0 (today's existing default) instead of AI-prefilled, and the parent counts by hand exactly as they do today. Nothing blocks on AI availability.

## Flow

1. Worksheet generated in-app (existing `ws_*` generators, unchanged) → a `sheets` row is written at generation time with `questions` (rendered sheet HTML/text), `answer_key` (the `ws.ans` block strings + keyLabel), `mtotal` (`wsQuestionCount(CURWS)`), status `pending_upload`. Printed as today.
2. Kid does it on paper.
3. Parent opens that sheet in-app, taps "Upload photo" (new button in the existing worksheet actions row), picks/snaps the photo → stored, `grade-sheet` invoked.
4. Parent taps "✓ Done — level up" as today — `openMasteryCheck` opens the existing modal, but now `mCorrect` pre-fills to `ai_verdict.estimated_correct` (if available) instead of 0, with the AI's `note` shown under the count. Parent can still type/step the number to any value before confirming.
5. Existing "✓ Confirm & level up" button (`confirmMastery`) now, in addition to its existing level-up logic, writes one `points_ledger` row for `mCorrect`'s final value, sheet → `approved`, `points_awarded` set, `final_verdict` saved. Points post on every confirm regardless of whether the 80% level-up threshold was met — a partial-credit sheet still earns partial points.
6. Wallet screen per kid: balance (progress-ring stat), streak, list of sheets awaiting review, ledger history, "Paid out — reset to 0" button (confirmation prompt, writes a `-balance` ledger row — never deletes history, so past payouts stay auditable).
7. Kid's own device: read-only wallet view (balance + streak + recent history), live via Supabase realtime — no upload/approve controls exposed there.

## Visual reskin — Hybrid Zen-Play

Applies site-wide (nav, Overview/Sarah/Mirayah tabs, worksheet display, ladder rungs, blank task sheets), not scoped to the new screens only:

- Background: soft cream → pale lavender gradient (`#fdf6ec` → `#eef3ff`)
- Cards: white, rounded (20px), soft shadow, thin warm-gray border
- Stat display: conic-gradient progress ring (warm orange `#ffb069` progress arc against pale lavender track) — used for both the points balance and (where sensible) existing ladder-rung progress
- Buttons: pill-shaped, primary = solid violet (`#5b4a8a`) on white text, secondary = cream fill with violet border/text
- Typography/spacing: keep existing font stack, apply the card/pill/ring language consistently

Print output (worksheets, blank task sheets) is unaffected — this reskin is screen-UI only; printed sheets keep their current plain, ink-efficient styling.
